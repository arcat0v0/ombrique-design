# 2026-11-05 编辑器 UI 大改设计

## 意图

参考 pen.dev 的画布优先体验：默认只保留画布、紧凑顶栏和左侧 48px 图标轨；页面、图层、资产、变量、历史、评论等面板全部默认收起；右侧属性面板仅在选中图层后出现。编辑器的全部既有能力仍可从图标轨、工具菜单和按需抽屉访问。

目标不是删除功能，也不是改变 TSX 源码、文档模型或命令系统，而是让默认界面围绕画布组织，让面板在任务需要时才出现。

## 目标、非目标与反目标

目标：

- 默认隐藏页面与图层，默认不显示属性面板。
- 选中元素后自动显示属性面板；可手动隐藏，下一次选择不同图层时再次显示。
- 左侧图标轨提供页面、图层、资产、变量、版本历史、编辑历史、评论入口。
- 评论工具、评论请求、重命名请求仍能自动打开对应左侧抽屉。
- 画布保持全幅；抽屉和属性面板叠在画布之上，不挤压原生 WebContentsView。
- 缩放、适应画布、显示/隐藏属性面板可在画布右下角操作。
- 兼具设计一致性的暗色真黑主题、Inter 字体和清晰层级。

非目标：

- 不重构属性检查器内部控件。
- 不变更快捷键、文档命令、TSX 源码或持久化格式。
- 不新增响应式手机编辑器布局；本产品是桌面设计工具。
- 不重做启动工作区的业务功能。

反目标：

- 以隐藏入口为代价制造“简洁”，导致现有能力不可达。
- 只改 CSS 而遗留 Electron 原生画布的旧边界约束。
- 用渐变、玻璃、发光、彩色图标方块等装饰取代清晰层级。
- 把属性面板恢复为常驻第三栏。

## 约束

- React + TypeScript + Tailwind CSS v4 + shadcn/ui；继续使用既有组件。
- WebGPU 画布是独立 Electron `WebContentsView`，由 React 通过 `updateCanvasBounds` 定位。
- 主进程曾以 `x < 120` 拒绝边界，并以 240px/280px 固定三栏作为 fallback；渲染端也有 `rect.x < 120` 守卫。
- Electron 原生画布覆盖普通 renderer DOM；所有可交互 HTML 外壳必须处于原生视图前景。
- 弹窗和菜单已有针对旧侧边栏的物理锚定逻辑，不破坏其可用性。
- 项目索引和治理文件在任务完成后通过 AOCI 维护。
- 不新增代码注释。

## 方案比较

### 方案 A：保留三栏，仅默认折叠固定面板

改 `ResizablePanel` 默认尺寸并在选中时切换右侧面板。实现最少，但原生画布仍被侧栏挤压，折叠状态与画布 bounds、fallback 布局和弹窗锚点耦合，达不到 pen.dev 的全幅画布感。未采用。

### 方案 B：画布优先，HTML 面板作为按需覆盖层（采用）

编辑器主体改为“顶栏 + 48px 左图标轨 + 全幅画布舞台”。左侧各面板和右侧属性面板使用绝对定位覆盖层，原生画布边界始终覆盖整个画布舞台。新增独立 `EditorWorkspace` 状态模型管理抽屉与属性面板，新增 `CanvasControls` 承载缩放和属性面板开关。同步移除主进程/渲染端的 `x < 120` 守卫和旧三栏 fallback 假设。该方案最贴合目标，且保留所有既有面板实现与 action 接线。

### 方案 C：把工具栏全部移入画布 WebContentsView

视觉最接近 pen.dev，但画布 runtime 是独立 bundle，顶栏菜单、文档状态、Electron 窗口控件、弹窗锚定均需跨进程重建，风险与改动面显著增大。未采用。

## 交互与状态

- `drawerTab` 默认是 `null`；每次打开项目从默认值开始，不持久化展开状态。
- 点击图标轨的展开按钮打开“图层”；再次点击或点击当前标签收起。
- 点击其他标签切换抽屉；点击当前标签收起。
- `commentsTabRequest`、`Ctrl+R` 重命名请求、评论工具切换自动打开对应抽屉。
- `inspectorVisible` 是用户偏好，仅持久化这一布尔值；选中新图层时恢复为显示。
- 无选区时不渲染属性面板；选中图层时可关闭，关闭后通过画布右上角或缩放条重新显示。
- 抽屉与属性面板有明确的标题、关闭按钮和可访问名称；保留键盘焦点与 tooltip。

## 视觉方向

采用 `true-black-flat` app style（seed 872251404）：#080808 暖近黑地面、#111111 表面、#1f1f1f 结构线、白色主文本、#b4b4b4/#949494 两级灰；少量 lime 仅用于产品状态标记。Inter 作为唯一界面字体并随桌面构建本地打包，避免网络字体依赖。几何改为方形或全圆角两种端点，移除毛玻璃、渐变、静态阴影和脉冲圆点。工作区启动页同步去掉渐变、micro-label 和图标方块，使打开项目前后为同一套语言。

方向红raw：无。画布仍用独立 WebContentsView，因此未采用 sheet 中的浅色双面板 builder blueprint；保留 true-black-flat 的颜色、字体、密度和单一 lightness-step 规则。

## 验证标准

1. 单元测试覆盖：默认收起、图标轨打开页面/切换抽屉、选中触发属性面板、隐藏后新选区恢复、事件驱动抽屉、完整画布 bounds 报告。
2. `editor-ui` 与 `desktop` 类型检查、测试、Biome（限定改动文件）通过。
3. `pnpm --filter @ombrique/desktop build` 成功；生产构建经 app inspector 在 1440/768/390 检查无 FAIL。
4. 真实 Electron E2E 启动示例项目并生成 shell/canvas 截图；真实 shell 状态脚本验证默认无抽屉、页面/图层抽屉可打开、选择事件打开属性面板且画布 bounds 不变。
5. 人工查看默认、页面抽屉、图层抽屉、选中属性面板和最终工作区截图，确认无遮挡、无错位、文字可读。

## 留给实现者的决定

- 左侧抽屉宽度 240px，属性抽屉宽度 280px；图标轨 48px。
- 缩放条固定在画布右下，诊断信息叠在左下，页面名标记叠在左上。
- 属性面板关闭偏好使用 `localStorage` 的 `ombrique-editor-workspace` 键，仅存 `inspectorVisible`。
- 工作区与画布背景统一为 #080808；Inter WOFF2 从系统字体转换为本地资源并随构建输出。
